📖 使用说明

1. 快速开始

  1. 等待右上角显示 「● 模型就绪 (本地)」（首次约 1~2 秒，模型权重约 890KB，全部加载到浏览器本地内存，不依赖任何云端推理）。
  2. 在工作台选择四种输入方式之一：
    • 图片识别：点击按钮上传本地人脸照片（也可直接点击下方「演示人脸」图）；
    • 视频文件：选择一段含人脸的本地视频（自动循环播放并逐帧检测）；
    • 实时摄像头：浏览器会请求摄像头权限（仅本地使用，画面不上传）；
    • 屏幕画面：选择浏览器窗口/整个屏幕/应用窗口，可演示含人脸的屏幕内容。
  3. 点击 ▶ 开始识别。右侧将实时显示 7 类情绪概率、置信度与几何特征。
  4. 情绪稳定后，下方推荐歌曲自动更新；点击 ▶ 播放，👍/👎 会参与个性化推荐。
  5. 情绪联动自动切歌：默认开启。识别到稳定情绪（置信度 ≥45% 且连续 2 帧一致）后自动播放该情绪排名第一的歌曲；情绪发生变化时旧曲淡出、新曲淡入，实现实时换歌。可在「情绪识别结果」卡片中一键关闭。

🌐 在线地址：https://cyljy.github.io/emotune/（GitHub Pages，HTTPS 环境下摄像头与屏幕采集权限均可正常授予）

2. 演示人脸

页面内置 7 种情绪 × 3 张 = 21 张 AI 生成的高真实感人像（中性、开心、悲伤、愤怒、恐惧、厌恶、惊讶），点击任意一张即自动切换到图片模式并识别，方便课堂/答辩演示。

3. 本地曲库与在线歌曲

  • 本地曲库：内置 13 首程序合成的器乐片段（mp3），首次推荐时会在浏览器本地完成音频特征分析（BPM、调式、亮度等），结果缓存在 localStorage，二次访问无需重复分析。
  • 在线歌曲：通过 iTunes Search API（JSONP）按情绪关键词检索，返回正版 30 秒试听。需联网；离线时本地曲库完全可用。

4. 环境要求与隐私

  • 推荐 Chrome / Edge 90+；摄像头与屏幕采集需通过 localhost 或 HTTPS 访问。
  • 隐私安全：人脸图像与视频全程只在浏览器内计算，不采集、不上传、不存储；唯一涉及网络的请求是「在线歌曲检索」。

5. 常见问题

  • 检测不到人脸？保证人脸占画面 15% 以上、正脸、光线充足；侧脸/遮挡会降低置信度。
  • 摄像头黑屏？检查浏览器权限设置；被其他程序占用时先释放。
  • 情绪跳变？系统内置 EMA 平滑 + 滑窗投票，正常情况下会收敛到稳定结果。

🧠 算法说明（全部经典、高效、可解释）

一、人脸检测：Tiny Face Detector（Tiny-YOLOv2 简化版）

9 层全卷积网络，输入缩放至 320×320，在特征图上以 12 个 anchor box 直接回归人脸框位置与置信度，单次前向传播完成检测（复杂度 O(W·H)），权重仅 190KB，CPU 单帧 <15ms。

二、表情分类：Face Expression Net（8 层轻量 CNN）

以对齐后的人脸区域为输入，经 3 组 Conv+ReLU+Pool 与 2 层 FC 输出 7 类概率：

softmax(W·h + b)，P ∈ {neutral, happy, sad, angry, fearful, disgusted, surprised}

权重 310KB，单帧 <10ms。同时由 FaceLandmark68Net 回归 68 个关键点，用于计算几何辅助证据（FACS 面部动作单元近似）：

  • 微笑曲率 = 嘴角相对嘴中心的上抬量 / 嘴宽（AU12）
  • 眼睛开度 EAR = 眼高和 / (2·眼宽·瞳距)（AU5/6）
  • 挑眉幅度、眉间距离（AU1/4）、张嘴程度（AU26）、鼻翼间距（AU9）

几何特征既用于结果可解释性展示，也可与 CNN 概率做交叉校验。

三、时序平滑（稳定情绪输出）

单帧表情概率存在抖动，采用两级平滑：

① 指数滑动平均：S_t = α·x_t + (1−α)·S_{t−1}，α = 0.55（兼顾响应速度与稳定性）

② 滑窗多数投票：最近 7 帧 argmax 情绪中出现次数最多者作为稳定情绪，配合票数一致率输出。

四、歌曲旋律情绪识别（纯前端 DSP，全部本地计算）

对音频做 STFT（4096 点汉明窗保证低频频率分辨率、65 抽头加窗 sinc 抗混叠 FIR 重采样至 ~11kHz）后逐帧提取：

  • 节奏 BGM：低频段(<260Hz, 鼓/贝斯节拍层)谱通量构成 onset 包络 → 自相关求节拍周期（带以 115BPM 为中心的节拍先验加权，抑制倍频歧义）→ BPM；峰值密度反映节奏密度。
  • 调式：将 55–2000Hz 能量折叠为 12 维色度向量（Chroma），与 Krumhansl-Kessler 大/小调感知模板在 12 个根音上做相关：modeScore = ρ(chroma, KK_major) − ρ(chroma, KK_minor)，大调→正效价，小调→负效价。
  • 音色/音区：谱质心（明亮度）、谱平坦度（噪声/粗糙感）、能量加权平均音高（音区高低）、RMS 动态范围。

最终映射到 Russell 效价-唤醒二维情绪空间：

Arousal = 0.60·BPM_norm + 0.20·OnsetDensity + 0.20·Dynamics

Valence = 0.70·ModeScore + 0.15·Brightness + 0.15·Register + 0.10·Harmonicity

同时按「调式 × 节奏」规则表给出离散情绪类别（快+大调=欢乐、快+小调=愤怒/惊讶、中速+小调=恐惧/厌恶、慢+大调=平静、慢+小调=悲伤），与连续 VA 坐标共同参与推荐打分。

整体复杂度 O(N·logM)（N=采样点数，M=FFT 窗长），30 秒音频在浏览器中约 1~2 秒完成，结果缓存于 localStorage。

五、推荐算法（四因子加权 + 个性化 Bandit）

人脸情绪同样映射到 (V,A) 空间（如 happy=(0.75,0.72)、sad=(−0.72,−0.45)、angry=(−0.58,0.88)…），对每首候选曲计算：

Score = 0.40·exp(−1.8·d²_VA) + 0.35·Sim(标签) + 0.15·(1−|BPM_n − A|) + 0.10·Feedback + ε

  • VA 匹配：情绪坐标欧氏距离的高斯核，d_VA=‖曲VA − 人VA‖₂；
  • 标签匹配：Plutchik 情绪轮相邻度矩阵（同情绪=1，相邻≈0.5，对置≈0.3），允许"悲伤时也推荐舒缓曲"的软匹配；
  • 律动匹配：唤醒度高的人偏好快节奏，使 BPM 归一值贴近目标唤醒度；
  • 个性化反馈：用户 👍(+1)/👎(−1) 记录写入 localStorage，构成轻量 Contextual Bandit；ε∈[−0.02,0.02] 随机扰动保证探索，避免推荐列表固化。

复杂度 O(K)（K=曲库规模），毫秒级完成排序。

六、在线歌曲接口

iTunes Search API（JSONP 方式调用，免密钥、无 CORS 限制）：按当前情绪选择的检索词请求，返回正版 30s 试听链接，前端再按同一套评分逻辑排序展示。

七、情绪联动自动切歌策略（实时换歌）

目标：表情变化 → 音乐实时跟随，同时避免"抖动换歌"破坏听感。采用三道闸门 + 平滑过渡：

  1. 置信度闸门：仅当 confidence ≥ 0.45 时进入判断，低置信度（侧脸、遮挡、运动模糊）不触发切歌。
  2. 时序一致性闸门：voteAgree ≥ 0.60（7 帧滑窗投票比例）且连续 2 帧判定为同一情绪，才算"情绪已改变"——等价于中值滤波，抑制单帧误判。
  3. 最小换歌间隔闸门：距上次切歌 ≥ 1.8s 才允许再次切换，形成时间维度上的迟滞（hysteresis），杜绝连续切歌。

通过闸门后，取该情绪下 Score 排名第 1 的曲目（第五节的四因子加权结果，含用户 👍/👎 反馈），执行音量包络交叉淡化：旧曲 220ms 线性淡出 → 切换音源 → 新曲 550ms 线性淡入（requestAnimationFrame 驱动，volume 归一化到 [0,1]），听感上无爆音、无硬切。

状态机：idle →(稳定情绪) playing →(情绪变化且通过闸门) switching →(淡入完成) playing；playing 状态下若推荐首位与当前播放曲目相同则不重复加载。

复杂度：每帧仅一次情绪比较 O(1)，切歌时 O(K) 重排（K=曲库规模），实时帧率不受影响。
